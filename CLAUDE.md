# smartldqr (ldqr)

## Project

A local-first **merchant point-of-sale (POS)** app for small retailers. The flow:

1. **Onboarding** — a merchant enters their details (`merchant_name`, `business_name`, `category`, `upi_id`). Completing it unlocks the app; the gate persists so it only runs once.
2. **Catalog** — manage the product catalog / inventory: add, inline-edit, and delete SKUs (name, price, category, stock count). Items can be added to the basket from here.
3. **Home** — shows the current basket (item count + total) and routes to checkout.
4. **Checkout** — lists the basket, shows a **simulated** QR code (not a real payment URI), and "Simulate Scan" logs a transaction and clears the basket.
5. **Confirmation** — success screen with the transaction id/amount.
6. **Settings** — placeholder only.

All data (SKUs, basket, transactions) persists **on-device via SQLite**. There is no backend/network call; payment is simulated in this phase.

### Target platforms
- **Primary: Android tablet, 2560×1600 (10").** Layouts must look correct here.
- **Phone** (Android/iOS) — must keep the existing single-column layouts unchanged.
- iOS (`ios.supportsTablet: true`) and web (`react-native-web`, static output) are also configured, but the device target driving layout decisions is the Android tablet.

- **`src/services/`** — the SQLite data layer (see next section).

- **`src/hooks/`** — `use-responsive.ts` (tablet breakpoint), `use-color-scheme.ts` / `.web.ts`, `use-theme.ts`.
- **`src/types/`** — `sku.ts`, `basket.ts`, `transaction.ts` data shapes.
- **`src/components/`** — shared UI, mostly Expo template: `themed-text`, `themed-view`, `external-link`, `ui/collapsible`, plus `screen-placeholder` (used by Settings).
- **`src/constants/theme.ts`** — colors/fonts/spacing (template). ⚠️ Defines `MaxContentWidth = 800` and `BottomTabInset` that are currently **unused** — do not start applying `MaxContentWidth` at the root (see Conventions).
- **`src/global.css`** — CSS font-family variables for web.
- **`assets/`** — app icons / splash images.
- **`scripts/reset-project.js`** — one-time template reset (⚠️ destructive).
- Config: `app.json`, `tsconfig.json`, `eslint.config.js`, `package.json`.

## Services & Data Layer

Everything persists through one SQLite database, `ldqr.db`. **All access goes through `db.ts`.** Each store mirrors the method names of the (never-registered) `NativeModules.*Module` objects the screens originally referenced, but returns typed values directly (no JSON-string round-tripping).

### `src/services/db.ts`
The shared connection + schema. Opens `ldqr.db` lazily and exactly once (all stores await the same promise → one connection, one migration pass), enables WAL, and `CREATE TABLE IF NOT EXISTS` for `skus`, `basket_items`, and `transactions`.
- `getDb(): Promise<SQLiteDatabase>` — the shared handle every store uses.
- `generateId(): string` — UUID-shaped id generator shared by the stores.

### `src/services/sku-store.ts` — `SkuStore`
Catalog/inventory. Returns typed `SkuItem`(s).
- `getAllActiveSkus()` → `SkuItem[]` (where `is_active = 1`, ordered)
- `getSkusByCategory(category)` → `SkuItem[]`
- `getSkusByRecTag(tag)` → `SkuItem[]`
- `getSkuById(skuId)` → `SkuItem | null`
- `insertSku(sku: Partial<SkuItem>)` → `boolean` (generates `sku_id`/`created_at`, defaults `is_active = 1`)
- `updateSku(sku: Partial<SkuItem>)` → `boolean`
- `deleteSku(skuId)` → `boolean` — **soft delete** (`is_active = 0`), so the row stays resolvable for historical transaction snapshots

### `src/services/basket-store.ts` — `BasketStore`
- `addItem(sku: Partial<SkuItem>)` → `boolean` — **upsert by `sku_id`**: if already in the basket, bumps quantity and recomputes subtotal; otherwise inserts a new line
- `getBasketItems()` → `BasketItem[]`
- `getBasketTotal()` → `number` (`SUM(subtotal)`)
- `clearBasket()` → `boolean`

### `src/services/transaction-store.ts` — `TransactionStore`
- `logTransaction({ total_amount, payment_method, basket_snapshot, item_count })` → `string` (the generated `transaction_id`)

## Conventions

- **TypeScript strict mode** (`tsconfig.json` → `strict: true`). Path aliases: `@/*` → `src/*`, `@/assets/*` → `assets/*`.
- **Tablet breakpoint**: `isTablet = width >= 768`, read via `useWindowDimensions()` through `src/hooks/use-responsive.ts` (`useResponsive()`). Use this hook — do not snapshot `Dimensions` (it won't update on rotation/resize).
- **Never hardcode `maxWidth` or a fixed `width` at the root / navigator / container level.** There is intentionally none in the codebase; reintroducing one is what causes the "narrow centered column" failure. (Note the unused `MaxContentWidth = 800` in `theme.ts` — leave it unused.)
- **Two-column on tablet, single column on phone.** Phone layouts must stay byte-for-byte unchanged: gate every tablet style behind `isTablet`, e.g. `style={[styles.x, isTablet && styles.xTablet]}`, and branch JSX rather than mutating the phone tree. Tablet screens add `TABLET_H_PADDING` (48px) horizontal padding.
- **Always use expo-sqlite via `db.ts`** (`getDb()`). Never call `SQLite.openDatabaseAsync` directly elsewhere; add new tables to the migration in `db.ts`.
- **Install native deps with `npx expo install`** (not raw `npm install`) so versions match the SDK. Per `AGENTS.md`, read the exact `https://docs.expo.dev/versions/v56.0.0/` docs before writing code.

## Known Issues

> **Status:** both items below were **fixed in code** during the session that authored this file. Both fixes depend on the SQLite/orientation native config, so they require a native rebuild —
> `npx expo prebuild --clean && npx expo run:android` — to take effect, and have **not yet been verified on a tablet/emulator**. They are kept here until that verification happens.

- [x] **Tablet layout: "narrow centered column with black sidebars."** Correction to the original diagnosis: there is **no** root-level width constraint (verified — zero `maxWidth`/`width` matches in the codebase, and `useWindowDimensions` was never used). The black sidebars were the **OS letterboxing** the app because `app.json` had `"orientation": "portrait"`, which pillarboxes a portrait-locked window on a landscape tablet. Fixed by `"orientation": "default"` + `"ios.supportsTablet": true`, plus per-screen responsive layouts via `useResponsive()`. ⏳ Pending rebuild + on-device check.
- [x] **`getAllActiveSkus` null error on Catalog.** `NativeModules.SkuModule` was `null` because no native module exists in the repo (the `NativeModules as {...}` cast lied to the compiler). Replaced with the JS `SkuStore` (`src/services/sku-store.ts`) backed by expo-sqlite through `db.ts`. ⏳ Pending rebuild (expo-sqlite is native, so it needs the dev build too).

- **`package.json` / `package-lock.json`** — manage dependencies via `npx expo install`, not by hand.
- **`tsconfig.json`, `eslint.config.js`, `.gitignore`** — toolchain config.
- **`expo-env.d.ts`** — generated, gitignored.
- **`/ios`, `/android`** — generated by `expo prebuild`, gitignored; never hand-edit.
- **`scripts/reset-project.js`** — ⚠️ **destructive**: deletes/moves `/src` and `/scripts`. Never run during feature work.
- **`assets/`** — app icons / splash.
